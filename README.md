# 🏛️ 场地借用管理系统 (Venue Rental System)

基于 **Google Sheets + Google Apps Script** 打造的轻量级场地/教室借用管理系统。不需要额外的数据库或服务器，Google Sheets 本身就是数据库，Apps Script 提供后端逻辑和网页服务，管理员和公众各自看到不同的页面。

## ✨ 功能特色

- **管理端**：可搜索/按栋号筛选的场地多选界面、24 小时制时间选择、连续多天借用、按星期重复借用（例如"每周六"）、编辑与删除、批量删除（防呆二次确认）。「填写人」栏位留空提交会自动带入当前登入者的 Google 账号姓名 + email，不用每次手动打字。
- **同场地同时段防呆**：新增/修改借用记录前会自动扫描冲突，撞档直接拦截，不会让同一场地同一时段出现两笔记录。
- **公众日历视图**：FullCalendar 呈现的月/周/列表视图，点击活动可看借用详情。
- **公众矩阵总表**：场地 × 日期的网格视图，一眼看出整月每个场地的使用状况，支持按行政单位颜色区分。
- **🚧 场地特殊状态**：管理端可以直接勾选场地 + 日期，打勾标记"维修"、"考试场地"、"不外借"之类的状态（可无限扩充，不是固定选项），跟一般借用记录分开储存、互不冲突拦截，纯粹标记 + 颜色显示用途；矩阵总表和公众日历都会同步显示这些标记。
- **权限管控**：管理端网址只有白名单里的 Google 账号能打开，所有写入操作（新增/修改/删除）在服务器端二次校验，无法绕过。
- **操作留痕**：所有新增/修改/删除都会记一笔操作日志（含真实 Google 账号），删除的记录会先进回收站，不会直接消失。
- **定期自动清理**：回收站和操作日志可以设定保留期限，到期自动清理，不用手动维护。

## 🧩 技术架构

| 组件 | 说明 |
|---|---|
| **数据库** | Google Sheets（借用记录按月分表，另有场地编号/回收站/操作日志表） |
| **后端** | Google Apps Script（`Code.gs` + `Cleanup.gs`） |
| **前端** | `HtmlService` 渲染的三个网页，用 Bootstrap 5 + 原生 JS 写成 |
| **日历组件** | [FullCalendar](https://fullcalendar.io/) 6 |
| **本地开发** | [clasp](https://github.com/google/clasp)（`.clasp.json` 已配置） |

## 🚀 部署方式

这是一个 Google Apps Script 项目，不是能直接跑起来的常规 Node/Python 服务，部署步骤如下：

### 1. 建立 Google Sheets + Apps Script 项目

1. 建一个新的 Google Sheets 表格。
2. 在表格里新建一张《场地编号》工作表，至少包含以下列：
   - **场地编号**、**场地名称**：管理端和公众页面显示用
   - **单位**：借用单位下拉选项来源
   - **管理员邮箱**：管理端白名单（脚本拥有者自动有权限，其他管理员的 Google 账号邮箱写在这一列）
   - （可选）在"单位"列的格子手动上底色，矩阵总表/日历会自动读取这个颜色来区分不同行政单位
3. 打开「扩展程序 → Apps Script」，把本项目的 `Code.gs`、`Cleanup.gs`、`Admin.html`、`Viewver.html`、`Table.html` 内容分别贴进对应的文件（文件名要完全一致，包括 `Viewver.html` 这个拼法）。
4. 《特殊状态》工作表不用手动建：第一次呼叫相关函数时（例如打开管理端）系统会自动建立，并预先放好"维修"/"考试场地"/"不外借"三个范例状态。想加新的状态种类，直接去这张表的 A 列多打一行文字即可；想让某个状态在矩阵总表/日历上有专属颜色，手动帮那一格上底色就行（不上色也能用，只是没有专属颜色）。
5. （可选，但建议开）开通 **Google People API**：管理端「填写人」栏位留空提交时，系统会自动带入当前登入者的 Google 账号姓名 + email（例如 `CHONG ZHI JIE 庄智杰 (zjchong@tsunjin.edu.my)`），这个"读取自己的姓名"需要多加一个 Google 进阶服务才能用。在 Apps Script 编辑器左侧「服务」旁边点 **+**，选「Google People API」加进项目即可，不用改任何设置，也不影响其他功能。不开这个服务也完全能正常使用系统，只是「填写人」留空时会退回只带入 email、没有姓名。

   如果习惯用命令行，也可以用 `clasp push`（`.clasp.json` 已经配置好对应的 Apps Script 项目 ID，`appsscript.json` 里也已经声明了这个进阶服务，但 `clasp push` 不会自动帮你在 Cloud 项目里"启用" People API——第一次用还是要照上面用编辑器的「服务 +」点一次，之后 `clasp push` 才不会出问题）。

### 2. 部署为网页应用

1. 点击「部署 → 新增部署」，类型选择「网页应用」。
2. 执行身份选择「以我的身份执行」，存取权限选择「知道网址的任何人」（公众日历/总表页面需要公开访问，管理端页面另有白名单拦截，不会因此外泄）。
3. 部署后会拿到一个网址，这个网址加上不同参数对应三个页面：
   - `?page=admin` 或不带参数：管理端（需白名单）
   - `?page=view`：公众日历视图
   - `?page=table`：公众矩阵总表
4. **之后每次改代码都要重新走一次「部署 → 管理部署 → 编辑 → 新版本」**，光是在编辑器里存档不会让线上网址生效。

### 3. 跑一次性设置/维护函数

有几个函数需要在 Apps Script 编辑器里手动选中、点击「运行」执行一次（第一次运行会跳出权限授权，正常允许即可）：

| 函数 | 用途 | 什么时候需要跑 |
|---|---|---|
| `installMonthlyCleanupTrigger()` | 建立每月自动清理回收站/操作日志的定时触发器 | 部署好之后跑一次即可，之后自动执行 |
| `migrateAllSheetsToSplitTimeSchema()` | 把旧结构（单一"时间"栏位）的月份工作表升级成新结构（"时间(开始)"/"时间(结束)"两栏） | 只有从旧版本升级上来、且有旧数据时才需要 |
| `fixTimeColumnFormatting()` | 修复被 Google Sheets 误转成日期格式的时间栏位数据 | 发现借用时间显示成一长串英文日期时跑一次 |

## 👩‍💼 管理员使用指南

1. 用白名单里的 Google 账号打开管理端网址。
2. 在左侧表单勾选场地、填写活动名称、借用单位、借用时间段（24 小时制）、使用日期、填写人（留空的话系统会自动带入你当前登入的 Google 账号姓名 + email，不强制一定要手动打字）。
   - 连续借用多天：额外填写「结束日期」。
   - 只在特定星期几重复借用（例如每周六）：勾选「按星期重复」，选择要重复的星期几，同样需要搭配「结束日期」。
3. 提交前系统会自动检查场地时段是否冲突，撞档会被拦截并提示原有的借用记录。
4. 右上角「📅 日历视图」「📊 总表视图」可以直接点开、或复制网址分享给其他人查看（不需要登入）。
5. 表格里的「🔗同批」按钮可以一键勾选同一次提交（连续多天/多场地）的所有记录，方便整批修改或删除。
6. 想标记场地"维修"、"考试场地"、"不外借"之类的特殊状态：勾选场地 + 设置日期（可以搭配「结束日期」/「按星期重复」）后，在下方「🚧 特殊状态」区块打勾要标记的状态，点「🚧 提交特殊状态」即可——不用填活动名称/借用单位/时间段，这跟一般借用记录是分开储存的。矩阵总表和公众日历会自动同步显示这些标记。想取消已经不需要的标记（例如维修完了），在右下角「🚧 特殊状态记录」清单里点「取消状态」。

## ⚠️ 已知限制

- 目前没有自动化测试；改动代码后建议至少做语法检查，有条件的话用 Playwright 离线渲染截图核对界面。
- Google Sheets 对写入的文本有自动格式转换的怪癖（尤其是看起来像时间/日期的文本），改动跟时间栏位相关的代码时要特别小心，详见 `CLAUDE.md`。
- 网页应用受 Apps Script 本身的配额限制（例如同时执行数、每日总运行时间），使用人数非常大时可能需要评估配额是否足够。
